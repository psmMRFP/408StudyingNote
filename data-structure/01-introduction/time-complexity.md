# 时间复杂度：数关键操作实际执行了多少次

## 核心问题

> 不根据代码“长得像几层循环”猜复杂度，而是追踪程序状态，计算关键操作实际执行次数。

分析顺序：

```text
确定输入规模 n
      ↓
找到反复执行的关键操作
      ↓
写出控制变量的状态变化
      ↓
计算关键操作执行次数 T(n)
      ↓
忽略常数倍和低阶项
      ↓
得到增长数量级
```

## 1. 单个线性循环

```c
for (int i = 0; i < n; i++) {
    x++;                         // 关键操作
}
```

只追踪 `x++`：

```text
i = 0       执行 x++
i = 1       执行 x++
i = 2       执行 x++
...
i = n - 1   执行 x++
i = n       条件 i < n 为假，退出
```

因此：

$$
T(n)=n
$$

增长数量级为：

$$
\Theta(n)
$$

408题目通常用大写 $O$ 表示时间复杂度，因此一般答 $O(n)$。严格地说，$\Theta(n)$ 表示上下界一致，比单独写 $O(n)$ 更精确。

> 结论来自 `x++` 执行了 $n$ 次，而不是来自“一层循环”这个外观。

## 2. 内层次数固定的嵌套循环

```c
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        x++;                     // 关键操作
    }
}
```

外层每取一个 `i`，内层的 `j` 都会经历：

```text
0, 1, 2, ..., n - 1
```

执行次数展开：

```text
i = 0       x++ 执行 n 次
i = 1       x++ 执行 n 次
...
i = n - 1   x++ 执行 n 次
```

所以：

$$
T(n)=\underbrace{n+n+\cdots+n}_{n\text{ 组}}=n^2
$$

因此时间复杂度为：

$$
O(n^2)
$$

这里得到 $n^2$，是因为共有 $n$ 组、每组恰好执行 $n$ 次；不是因为看到“两层循环”就直接写平方。

## 3. 内层次数依赖外层变量

```c
for (int i = 0; i < n; i++) {
    for (int j = 0; j < i; j++) {
        x++;                     // 关键操作
    }
}
```

不能把两层循环都当作执行 $n$ 次。对每个 `i` 单独计数：

```text
i = 0       j 无法进入循环，执行 0 次
i = 1       j = 0，执行 1 次
i = 2       j = 0, 1，执行 2 次
...
i = n - 1   执行 n - 1 次
```

总次数：

$$
T(n)=0+1+2+\cdots +(n-1)
$$

$$
T(n)=\frac{n(n-1)}{2}=\frac{1}{2}n^2-\frac{1}{2}n
$$

只保留增长最快的部分，并忽略常数系数：

$$
O(n^2)
$$

### 机器视角

内层循环的工作量不是一个固定值，而是由当前 `i` 决定：

```text
外层状态 i ──决定──> 本轮内层执行次数
```

因此，应先写求和式，再判断增长速度。

## 4. 按倍数变化的循环变量

```c
int i = 1;

while (i < n) {
    i *= 2;
}
```

状态变化：

```text
循环开始前：i = 1
执行 1 次后：i = 2
执行 2 次后：i = 4
执行 3 次后：i = 8
...
执行 k 次后：i = 2^k
```

循环在 `i >= n` 时停止，所以最小的执行次数 $k$ 满足：

$$
2^k\ge n
$$

当 $n>1$ 时：

$$
k=\lceil\log_2 n\rceil
$$

因此：

$$
O(\log n)
$$

复杂度为对数级的原因是：状态每变化一次，`i` 都扩大为原来的2倍。

> 在复杂度记号中，对数的底通常可以省略。不同常数底之间只相差常数倍，不影响增长数量级。

## 5. 前后两段代码也要分别计数

```c
for (int i = 0; i < n; i++) {
    x++;
}

for (int j = 0; j < n * n; j++) {
    y++;
}
```

不要仅凭“两段循环前后排列”判断结果。实际计数：

```text
x++：执行 n 次
y++：执行 n² 次
```

所以程序的关键操作总次数为：

$$
T(n)=n+n^2
$$

当 $n$ 增大时，$n^2$ 比 $n$ 增长得更快，因此：

$$
O(n^2)
$$

这里不是背某条命名规则，而是先把两段代码的实际工作量计入总次数，再保留增长最快的项。

## 6. 分支必须先说明讨论哪种情况

```c
if (target == a[0]) {
    return 0;
}

for (int i = 1; i < n; i++) {
    if (a[i] == target) {
        return i;
    }
}
```

关键比较 `a[i] == target` 的次数取决于输入：

```text
最好情况：target == a[0]，很快返回
最坏情况：最后才找到或始终找不到，需要检查整个数组
```

因此，分析前必须明确是在讨论：

- 最好时间复杂度；
- 最坏时间复杂度；
- 平均时间复杂度。

408若没有特别说明，算法复杂度题通常重点考虑最坏情况，但仍应结合题目语境判断。

## 7. 常见误判

### 误判一：一层循环一定是 $O(n)$

错误。循环变量可能按倍数变化：

```c
for (int i = 1; i < n; i *= 2) {
    x++;
}
```

`i` 经历 $1,2,4,8,\ldots$，执行次数是对数级。

### 误判二：两层循环一定是 $O(n^2)$

错误。内层次数可能不是 $n$：

```c
for (int i = 0; i < n; i++) {
    for (int j = 0; j < 10; j++) {
        x++;
    }
}
```

关键操作执行：

$$
T(n)=10n
$$

所以是 $O(n)$。

### 误判三：只数循环层数，不看变量依赖

遇到 `j < i`、`j < n - i`、`j *= 2` 等条件时，必须写出每轮的实际次数或求和式。

### 误判四：先写 $O(\cdot)$，再倒推理由

正确顺序应当是：

```text
状态变化 → 执行次数 T(n) → 增长数量级
```


## 最终记忆

```text
时间复杂度不是看代码外形。

如果我是 CPU：
    当前变量是什么值？
    下一步会变成什么值？
    关键操作在每个状态下执行几次？

把所有执行次数写成 T(n)，
最后才把 T(n) 化成复杂度。
```
