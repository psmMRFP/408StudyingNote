# 顺序表：连续内存中的线性表

## 核心模型

> **顺序表 = 一段连续存放元素的内存 + 当前有效元素个数。**

最简单的静态顺序表可以理解为“定长数组＋长度”：

```cpp
const int MAX_SIZE = 100;

struct SqList {
    int data[MAX_SIZE]; // 容量固定为 MAX_SIZE
    int length;         // 当前有效元素个数
};
```

初始化：

```cpp
void initList(SqList &list) {
    list.length = 0;
}
```

此时不必清零整个数组。`length == 0` 已经表示没有有效元素。

> 未成为有效元素的数组位置可能保存未初始化值。程序不得读取并使用这些值；“内存位置存在”不等于“其中存在顺序表元素”。

## 1. 内存中实际存了什么

假设容量为6，当前状态是：

```text
下标           0       1       2       3       4       5
           +-------+-------+-------+-------+-------+-------+
data       |  10   |  20   |  30   |  40   |   ?   |   ?   |
           +-------+-------+-------+-------+-------+-------+
              <--------- 有效范围 --------->

length   = 4
capacity = 6
```

机器和程序之间的约定是：

```text
data[0] ~ data[length - 1]     有效元素
data[length] ~ data[capacity-1] 已分配但当前无效
```

`?` 只表示该位置的值不应被当作顺序表元素读取；它不保证物理比特为零。

## 2. “顺序”不是数值已经排序

“顺序存储”描述的是逻辑相邻元素与物理存储位置之间的关系：

```text
逻辑上相邻：第1个 → 第2个 → 第3个 → 第4个
物理上相邻：data[0], data[1], data[2], data[3]
```

以下顺序表同样采用顺序存储，尽管数值没有递增：

```text
[40][10][90][20]
```

## 3. 位序与数组下标

408题目通常使用从1开始的**位序**，C/C++数组下标从0开始：

```text
第 i 个元素  <==>  data[i - 1]
```

```text
位序：       1       2       3       4
下标：       0       1       2       3
         +-------+-------+-------+-------+
         |  10   |  20   |  30   |  40   |
         +-------+-------+-------+-------+
```

例如，第3个元素对应 `data[2]`。

## 4. 按位访问为什么是 O(1)

设：

- 数组首地址为 `base`；
- 每个元素占 `w=sizeof(int)` 字节；
- 访问下标为 `k` 的元素。

机器可以计算：

```text
address(data[k]) = base + k * w
```

例如只为说明计算过程，假设：

```text
base        = 1000
sizeof(int) = 4
k           = 6
```

则：

```text
address(data[6]) = 1000 + 6 * 4 = 1024
```

CPU不需要先访问 `data[0]` 到 `data[5]`。在408采用的RAM模型中，地址计算和一次内存访问按常数时间计，因此按位访问为：

```text
O(1)
```

实际计算机还存在Cache、TLB、缺页等因素；它们影响单次访问延迟，但不改变数据结构题所采用的渐进复杂度模型。

## 5. 插入：先保护旧数据，再写入新元素

### 5.1 目标状态

原顺序表：

```text
位序：       1       2       3       4
下标：       0       1       2       3       4
         +-------+-------+-------+-------+-------+
         |  10   |  20   |  30   |  40   |   ?   |
         +-------+-------+-------+-------+-------+

length = 4
```

在位序 `i = 2` 插入 `99`，目标是：

```text
[10][99][20][30][40]
```

插入位置对应 `data[i - 1] == data[1]`。但其中已有 `20`，直接写入会覆盖旧数据。

### 5.2 必须从后向前右移

每执行一条赋值后，数组状态如下：

```text
初始：
[10][20][30][40][ ?]

执行 data[4] = data[3]：
[10][20][30][40][40]

执行 data[3] = data[2]：
[10][20][30][30][40]

执行 data[2] = data[1]：
[10][20][20][30][40]

执行 data[1] = 99：
[10][99][20][30][40]

执行 length++：
length = 5
```

之所以从后向前，是因为每一步都先读取尚未被覆盖的源元素。

### 5.3 从前向后右移为什么错误

如果先执行：

```cpp
data[2] = data[1];
data[3] = data[2];
```

状态将变为：

```text
初始：                    [10][20][30][40][ ?]
data[2] = data[1] 后：    [10][20][20][40][ ?]
data[3] = data[2] 后：    [10][20][20][20][ ?]
```

第二条语句读取的 `data[2]` 已经不是原来的 `30`。尚未搬走的数据被提前覆盖，因此发生数据丢失。

### 5.4 完整代码

```cpp
bool listInsert(SqList &list, int i, int value) {
    // 具有 n 个元素时，合法插入位序为 1 ~ n+1
    if (i < 1 || i > list.length + 1) {
        return false;
    }

    if (list.length >= MAX_SIZE) {
        return false;
    }

    // 原下标 i-1 ~ length-1 的元素整体右移
    for (int j = list.length; j >= i; --j) {
        list.data[j] = list.data[j - 1];
    }

    list.data[i - 1] = value;
    ++list.length;
    return true;
}
```

循环边界对应的第一次和最后一次搬移：

```text
第一次：j = length
data[length] = data[length - 1]   搬最后一个有效元素

最后一次：j = i
data[i] = data[i - 1]             搬插入位置原来的元素
```

## 6. 插入复杂度：数搬移次数

设插入前有 `n` 个元素，在位序 `i` 插入，其中 `1<= i<= n+1`。

需要搬移的元素是原来的第 `i` 个到第 `n` 个，因此：

```text
M(n, i) = n - i + 1
```

| 插入位置 | 搬移次数 | 时间复杂度 |
| --- | ---: | --- |
| 位序 `n+1`，表尾 | `0` | `O(1)` |
| 位序 `1`，表头 | `n` | `O(n)` |

若 `n+1` 个合法插入位置等概率出现，平均搬移次数为：

```text
[n + (n - 1) + ... + 1 + 0] / (n + 1) = n / 2
```

因此平均时间复杂度为：

```text
O(n)
```

主要成本不是把 `value` 写入数组，而是为连续存储腾出一个位置。

## 7. 删除：后继元素依次覆盖前一个位置

原状态：

```text
位序：       1       2       3       4       5
下标：       0       1       2       3       4
         +-------+-------+-------+-------+-------+
         |  10   |  20   |  30   |  40   |  50   |
         +-------+-------+-------+-------+-------+

length = 5
```

删除位序 `i = 2` 的元素：

```text
先保存 data[1] = 20

执行 data[1] = data[2]：
[10][30][30][40][50]

执行 data[2] = data[3]：
[10][30][40][40][50]

执行 data[3] = data[4]：
[10][30][40][50][50]

执行 length--：
length = 4
```

最终只有前4个位置有效：

```text
有效： [10][30][40][50]
无效：                     [50]
```

删除操作通常不负责擦除最后一个物理位置；缩短 `length` 就已经把它排除在顺序表之外。

### 7.1 完整代码

```cpp
bool listDelete(SqList &list, int i, int &removed) {
    // 具有 n 个元素时，合法删除位序为 1 ~ n
    if (i < 1 || i > list.length) {
        return false;
    }

    removed = list.data[i - 1];

    // 后继元素从前向后覆盖前一个位置
    for (int j = i; j < list.length; ++j) {
        list.data[j - 1] = list.data[j];
    }

    --list.length;
    return true;
}
```

删除时从前向后左移，每一步读取的是右侧尚未被修改的元素。

## 8. 删除复杂度：仍然数搬移次数

删除前有 `n` 个元素，删除位序 `i`，其中 `1<= i<= n`。

删除后，需要把原来的第 `i+1` 个到第 `n` 个元素左移：

```text
M(n, i) = n - i
```

| 删除位置 | 搬移次数 | 时间复杂度 |
| --- | ---: | --- |
| 位序 `n`，表尾 | `0` | `O(1)` |
| 位序 `1`，表头 | `n-1` | `O(n)` |

若所有删除位置等概率出现，平均搬移次数为：

```text
[(n - 1) + (n - 2) + ... + 1 + 0] / n = (n - 1) / 2
```

因此平均时间复杂度为 `O(n)`。

## 9. 按位查找与按值查找

### 9.1 按位查找

“取得第5个元素”对应：

```cpp
int value = list.data[5 - 1];
```

机器直接根据首地址和下标计算地址，因此为 `O(1)`。

调用前仍应保证位序合法：

```text
1 <= i <= length
```

### 9.2 按值查找

未排序的顺序表无法根据值直接算出地址，只能逐个比较：

```cpp
int locateElement(const SqList &list, int target) {
    for (int index = 0; index < list.length; ++index) {
        if (list.data[index] == target) {
            return index + 1; // 返回从1开始的位序
        }
    }
    return 0;                 // 0 表示未找到
}
```

最坏情况下比较 `n` 次，因此为 `O(n)`。

> “随机访问”指根据位序/下标直接访问，并不表示根据任意元素值都能直接定位。

## 10. 动态顺序表

静态顺序表的数组容量固定。动态顺序表把元素放在动态申请的连续区域中：

```cpp
struct SeqList {
    int *data;   // 指向动态数组首元素
    int length;  // 有效元素个数
    int capacity;// 当前容量
};

void initList(SeqList &list, int initialCapacity) {
    list.data = new int[initialCapacity];
    list.length = 0;
    list.capacity = initialCapacity;
}
```

内存关系：

```text
栈上或对象内部的控制信息：

SeqList list
+----------------------+
| data ----------------+----+
| length   = 4         |    |
| capacity = 6         |    |
+----------------------+    |
                            v
动态申请的连续区域：
+------+------+------+------+------+------+
|  10  |  20  |  30  |  40  |  ?   |  ?   |
+------+------+------+------+------+------+
   0      1      2      3      4      5
```

`data` 本身是一个指针；元素位于它指向的动态数组中。

销毁时需要释放动态数组：

```cpp
void destroyList(SeqList &list) {
    delete[] list.data;
    list.data = nullptr;
    list.length = 0;
    list.capacity = 0;
}
```

## 11. 扩容：换一段更大的连续内存

下面采用“申请新区域→复制→释放旧区域”的明确实现，以观察扩容过程：

```cpp
bool expand(SeqList &list, int newCapacity) {
    if (newCapacity <= list.capacity) {
        return false;
    }

    int *newData = new int[newCapacity];

    for (int i = 0; i < list.length; ++i) {
        newData[i] = list.data[i];
    }

    delete[] list.data;
    list.data = newData;
    list.capacity = newCapacity;
    return true;
}
```

机器状态：

```text
扩容前：
list.data ──> [10][20][30][40]
length = 4, capacity = 4

申请新区域后：
old data  ──> [10][20][30][40]
newData  ──> [ ?][ ?][ ?][ ?][ ?][ ?][ ?][ ?]

复制后：
old data  ──> [10][20][30][40]
newData  ──> [10][20][30][40][ ?][ ?][ ?][ ?]

释放旧区域并修改指针：
list.data ──> [10][20][30][40][ ?][ ?][ ?][ ?]
length = 4, capacity = 8
```

在这一实现中，扩容不是让原数组原地变长，而是更换存储区域。一次扩容需要复制 `length` 个元素，因此该次操作为 `O(n)`。

某些内存分配接口或库实现可能在特定条件下原地扩展，但不能把它当作通用保证。408分析动态数组时，通常按照重新申请和搬移元素理解。

扩容后，指向旧元素地址的裸指针或引用可能失效：

```text
扩容前：p ──> 旧 data[1]
扩容后：旧区域已释放，p 不再指向有效元素
```

## 12. 顺序表的核心矛盾

```text
                    连续内存
                  /          \
                 v            v
      下标可直接换算地址      中间不能留下逻辑空洞
                 |            |
                 v            v
          按位访问 O(1)     插入/删除需要搬移
                              |
                              v
                         平均 O(n)
```

顺序表的性质几乎都来自“逻辑相邻元素存放在物理相邻的位置”。

## 13. 操作汇总

| 操作 | 机器实际动作 | 典型时间复杂度 |
| --- | --- | --- |
| 按位访问 | 首地址＋下标×元素大小 | `O(1)` |
| 未排序表按值查找 | 从前向后逐个比较 | `O(n)` |
| 表尾插入且容量足够 | 直接写入并增加 `length` | `O(1)` |
| 中间插入 | 后缀元素从后向前右移 | `O(n)` |
| 删除表尾 | 减少 `length` | `O(1)` |
| 中间删除 | 后继元素从前向后左移 | `O(n)` |
| 一次动态扩容 | 申请新区域并搬移全部有效元素 | `O(n)` |

## 14. 408易错点

1. 把位序 `i` 直接当作数组下标；正确下标是 `i-1`。
2. 插入的合法位序是 `1 ~ length+1`，删除的合法位序是 `1 ~ length`。
3. 插入右移必须从后向前，避免覆盖尚未读取的数据。
4. 删除左移必须从前向后读取右侧元素。
5. `length` 表示有效元素个数，`capacity` 表示已分配位置总数。
6. 删除后最后一个物理位置可能仍保留旧比特，但它已经无效。
7. 按位访问为 `O(1)`，不代表未排序表按值查找也是 `O(1)`。
8. 动态扩容后底层首地址可能改变，旧指针或引用可能失效。
9. `data[]` 连续，不代表整个结构体绝对没有填充字节；具体对象布局还受类型对齐规则影响。

## 最终机器模型

```text
顺序表
  = 连续的一排存储单元
  + length（有效元素数）
  + capacity（可用单元总数）

访问：地址 = 首地址 + 下标 * 元素大小
插入：从后向前右移 → 写入 → length++
删除：保存旧值 → 从前向后左移 → length--
查值：逐项比较
扩容：申请更大连续区域 → 搬移 → 释放旧区域 → 修改指针
```
