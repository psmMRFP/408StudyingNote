## 笔记约定

- 每个主题单独使用 Markdown 文件记录。
- 算法和数据结构优先使用 C/C++ 代码或伪代码解释；不强制纯 C，纯 C 表达过于繁琐时可使用适量、直观的 C++ 特性。
- 用户提供网页回答或其他原始材料时，以校正、去歧义、重组和补全为主，不机械照抄；整理后纳入对应章节。
- 计算机组成与操作系统优先展示机器状态、地址转换、寄存器/内存变化和执行步骤。
- 计算机网络优先展示报文结构、数据流向、状态变化及逐跳传输过程。
- 可在当前 Linux＋fish 环境中加入安全实操，并把命令、关键输出及其与408概念的对应关系写入笔记。
- 实操默认使用普通用户权限、只读查询或可回滚实验；不修改磁盘分区、引导配置、内核关键参数和系统关键服务。
- 任何需要 `sudo` 的命令都必须在执行前说明用途、风险和影响范围，并取得明确同意；未经同意不得执行。
- 自然语言只用于连接步骤、说明条件和总结结论，尽量避免含混表述。
- 代码用于帮助理解，不要求作为可运行项目组织。
- 绘图遵循“Mermaid负责关系，ASCII负责状态”，具体见[笔记编写与绘图规范](WRITING-GUIDE.md)。
- 章节内容按实际学习需求逐步添加，不预先堆积空笔记。
